ReleaseBound Support

About ReleaseBound

ReleaseBound is a local-first macOS application that independently verifies release outcomes for a software project you choose. It does not take an AI agent’s (or anyone’s) success report at face value; it checks the release facts itself.

Getting started

  1. Open ReleaseBound on your Mac.
  2. Choose the project you want to verify.
  3. Run verification for the release candidate.
  4. Review the verdict, the required gates, and the evidence.

How to select a project

Use “Choose Project Folder…” and pick the folder that contains your project. macOS asks you to grant access to that folder, and ReleaseBound only works with the folder you authorize. If the folder was moved or renamed after you authorized it, choose it again to refresh access.

How to verify a release candidate

With a project selected, start a verification run. ReleaseBound runs its required gates against your project and shows progress and results as they complete. When the run finishes you will see an overall verdict and the result of each gate.

Understanding verdicts

NOT VERIFIED
Verification has not been completed for the current candidate, so no readiness claim is made.
READY
The gates ReleaseBound currently checks were independently confirmed as passing for this candidate. This is not a guarantee of defect-free software or of App Store acceptance.
NOT READY
At least one required gate did not pass. Review the failing gate and its evidence.
BLOCKED
ReleaseBound could not independently confirm one or more required facts, so it does not report a pass. Resolve what is blocking verification and run it again.

Key concepts

Required Gates
The checks a release candidate must pass, such as build, tests, source state, signing, and packaging.
Evidence
The technical results behind each gate (for example results, hashes, and related details) so a verdict can be inspected.
Verified Baseline
A record of a last known verified release, used as a reference point.
Drift Detection
Comparison of a candidate against the verified baseline to surface differences that matter for release.
Verification History
A record of earlier verification runs, so you can see how readiness has changed.

Troubleshooting

The project cannot be selected

Choose the project folder again using “Choose Project Folder…” and grant access when macOS asks. Make sure the folder still exists at the same location and that you have permission to read it.

The build gate fails

Confirm the project builds on your Mac outside ReleaseBound with the same scheme and configuration, and that Xcode and its command line tools are installed. Then review the build gate’s evidence for the reported error.

The test gate fails

Run the project’s tests yourself to confirm the failure, then review the test gate’s evidence. A failing test is a real result; ReleaseBound does not ignore it.

Signing validation fails

Check that the signing identity and team configured for the project are available on your Mac and have not expired, and that the built product is signed as expected.

Packaging fails

Confirm the project can produce its distribution package with your normal tooling, then review the packaging gate’s evidence for the specific failure.

Verification becomes BLOCKED

BLOCKED means a required fact could not be independently confirmed — for example a needed tool is missing, access to the project was lost, or a required result was unavailable. Restore access or tools, then run verification again.

Evidence cannot be produced

Check that the project folder is still authorized and accessible and that the disk has free space, then run verification again. If it persists, contact support and describe which gate was involved.
